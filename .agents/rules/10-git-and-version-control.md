# Git & Version Control Standards

This rule governs Git hygiene, branching strategy, commit standards, and pull request generation across all projects owned by **Nitin Bharwad**.

---

## 1. Author & Identity

- **Author**: Nitin Bharwad
- All commits created in this repository must maintain clean Git attribution to Nitin Bharwad.

---

## 2. Branching Strategy

Maintain atomic, purpose-driven branches:
- **Feature Branches**: `feat/<short-description>` (e.g., `feat/auth-modal`, `feat/stripe-checkout`)
- **Bug Fix Branches**: `fix/<short-description>` (e.g., `fix/mobile-nav-overflow`, `fix/token-refresh`)
- **Hackathon Experiments / Spikes**: `spike/<idea-name>` (e.g., `spike/gemini-live-audio`)
- **Chore / Ops**: `chore/<description>` (e.g., `chore/upgrade-next-15`)

---

## 3. Conventional Commit Protocol

All commit messages must follow the Conventional Commits specification:
```
<type>(<scope>): <short imperative description>

[optional longer body detailing context & why]
```

**Permitted Types**:
- `feat`: New feature or user capability.
- `fix`: Bug fix or patch.
- `refactor`: Code reorganization with no behavior change.
- `style`: Formatting, whitespace, visual tweaks.
- `test`: Adding or updating test suites.
- `docs`: README, architecture notes, inline documentation.
- `chore`: Tooling, configs, dependency updates.

**Examples**:
- `feat(auth): integrate Supabase social login with PKCE`
- `fix(navbar): resolve hamburger menu layout shift on mobile viewports`
- `chore(deps): update tailwindcss to v4`

---

## 4. Pull Request (PR) Preparation

Every PR generated by the agent for Nitin Bharwad must include:
1. **Summary of Changes**: Bullet points of architectural changes.
2. **Why**: Context or link to issue/ticket.
3. **How to Test**: Step-by-step instructions for the reviewer.
4. **Visual Proof**: Screenshots or recordings for UI changes.
